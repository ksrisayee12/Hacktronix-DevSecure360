# Prompt Builder (`prompt_builder.py`)

This module is responsible for bridging the gap between the vulnerability scanner and the LLM agent by translating normalized scan findings into structured, actionable prompts for the AI.

## Overview

The AI patching pipeline relies on heavily structured prompts to instruct the LLM (like Ollama or Gemini) on exactly what to do. The `prompt_builder.py` script takes the output from the previous step (`normalized_findings.json`) and generates individual text files (`prompt_*.txt`) containing the full context and strict instructions for fixing each vulnerability.

## Input

- **Normalized Findings**: It reads `normalized_findings.json`, which contains a flattened, deduplicated list of vulnerabilities found across the codebase. Each finding must specify the `file_path`, `start_line`, `end_line`, and `snippet` (description).

## Process

1. **Load Findings**: The script loads the array of findings from the JSON file.
2. **Read Source Code**: For each finding, it dynamically reads the exact, current state of the vulnerable Python file directly from disk.
3. **Build Prompt String**: It constructs the prompt using a specific template. The prompt includes:
   - Metadata about the vulnerability (file, lines, description).
   - The **full** contents of the source file. Passing the full context is crucial because the agent needs to return the complete patched file to ensure the file isn't accidentally truncated or broken when overwritten.
   - Strict output instructions (the "TASK" block).
4. **Export to Disk**: It saves each prompt string into a separate `.txt` file inside the `prompts/` directory (e.g., `prompt_1.txt`, `prompt_2.txt`).

## The Prompt Structure

The prompt generated by `build_prompt()` is highly opinionated to ensure the LLM strictly outputs code rather than conversational text:

*   **Context**: Provides the exact location and description of the vulnerability.
*   **Full File Code**: The raw source code of the file.
*   **TASK Instructions**:
    *   Instructions to fix the specific vulnerability without altering unrelated logic.
    *   **CRITICAL Constraint**: The LLM must return ONLY valid Python code (no markdown fences like ` ```python `, no English text).
    *   **Summary Block**: The LLM is instructed to append a specific `# AGENT FIX SUMMARY:` comment block at the bottom of the file to explain its changes natively within the code.

## Execution

When run independently as a script, `prompt_builder.py` will automatically generate prompts based on `normalized_findings.json` in its same directory. 

```bash
cd backend/app/agent
python prompt_builder.py
```

However, it is typically orchestrated as "Step 2" of the full agent pipeline inside `agent.py`:
1. `normalizer.py` (Creates `normalized_findings.json`)
2. **`prompt_builder.py` (Creates `prompts/prompt_*.txt`)**
3. `ollama_llm_client.py` (Processes the prompts and overwrites the code)
